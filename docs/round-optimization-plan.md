# 每轮 Agent 工作优化计划

日期：2026-11-23。状态：待实施。本文件记录后续设计，不表示已经改动 pipeline、完成消融或确认性能收益。

目标是在保留现有外部循环和本地模型驱动方式的前提下，提高有效候选产出率、失败反馈质量和固定时间预算内的累计优化收益。方法参考 EngineAgent、MetaInfer 与 VibeServe；这些工作的任务、模型、硬件和准入规则不同，论文加速比不能直接视为本项目预期收益。

## 1. 固定边界

继续使用现有流程：

> 固定模型、硬件与负载 → 启动稳定引擎 → 每轮重新勘测 → 本地模型驱动 Agent 修改候选副本 → 停止稳定引擎、构建并重启候选 → 快速探测 → 功能、质量、配对性能评测 → 接受或回退 → 下一轮。

- Agent 默认由本地稳定目标引擎承载，不引入外部模型服务，也不并行加载多个完整模型。
- 新增角色优先顺序调用同一本地模型，以独立会话分工；不要求新增模型或 GPU。
- 模型、硬件、精度、负载、上下文、输出长度、thinking 与主指标按当次冻结配置执行。
- 正式配置保持每轮重新勘测；不以结构知识复用替代性能重测。
- 宿主整理事实并独立准入；优化方向和候选代码由 Agent 产生，不人工代写候选。
- GPU 快速探测和正式评测仍在候选重启后执行；本地 Agent 不通过 Shell 加载整模型。
- 只使用同次运行的历史。所有新增结论区分事实、Agent 解释与待验证假设。
- 普通失败按现有 pipeline 拒绝并进入下一轮；完整性异常保持停止，不绕过检查。

## 2. 当前基础

以下为计划制定时已存在的机制，实施前需以实际代码再次核对，避免重复建设：

| 机制 | 当前入口 | 本计划的增强方向 |
| --- | --- | --- |
| 每轮上下文、稳定身份和历史材料 | `src/vibeforge_v2/loop.py` 的 `context()` | 按当前任务选择证据，而非持续堆叠材料 |
| 宿主瓶颈摘要 | `src/vibeforge_v2/bottleneck.py` | 补充观测、执行路径、条件与未知项的对应关系 |
| 假设与工作笔记 | `prompts/engineer.md`、候选 `WORK_LOG.md` | 保存可供新会话使用的结构化任务卡 |
| 静态检查、CPU harness、重复候选检查 | `agent.py`、`checks.py`、`harness.py` | 保留现有门槛，增强诊断与复核 |
| 同次运行经验及实现库 | `experience.py`、`library.py` | 从改动结果扩展到有条件的假设状态 |
| 候选快速探测、功能、质量、配对性能 | `evaluate.py`、`feedback.py` | 对照假设反馈机制是否生效 |

当前经验按配置项、源码文件和宿主判定汇总，有助于去重；同一个文件可能包含不同机制，同一个机制也可能因接口错误、路径未激活或真实无收益而失败，需要进一步区分。

## 3. 任务与优先级

### P0-A：生成紧凑的每轮证据包与任务卡

借鉴 EngineAgent 的层次知识和 MetaInfer 的执行路径表示；先用普通 JSON/Markdown，无需引入图数据库。

宿主证据包包含：

1. 冻结目标、场景权重、主指标和退化约束。
2. 与目标相关的已测观测值、测量范围、来源文件和稳定源码身份。
3. 对应函数、模块、后端、shape、dtype，以及“已加载”与“实际调用”的证据差别。
4. 与当前路径有关的同次运行失败和接受记录。
5. 无法推导的未知项和证据缺口，不从 profiler 累计时间比推断真实利用率或可实现收益。

本地 Agent 依据证据自行选择假设，并形成任务卡：

```text
假设标识：
性能假设：
观测依据及来源：
目标调用路径：
适用条件与当前稳定身份：
预期可观测变化：
否定该假设的结果：
本轮修改边界：
需要执行的局部检查：
尚未确认的风险：
```

宿主只验证字段完整性、路径及证据身份，不把 Agent 的解释写成已证实结论。历史全文保留在磁盘，初始上下文优先提供与当前任务直接相关的条目。

验收：能从任务卡定位原始证据；未知值不被补造；任务卡不会替代候选真实改动或准入。记录输入 token 开销，与原上下文比较。

### P0-B：按假设与条件维护失败状态

在现有经验台账上增量扩展，不替换宿主事实来源。建议分别保存 `host_status` 与 `agent_interpretation`，以及父稳定哈希、实际 diff 身份、条件和证据路径。

| 状态 | 含义及后续处理 |
| --- | --- |
| 实现失败 | 接口、语法、构建或数值检查失败；只说明当前实现有问题 |
| 机制未确认 | 缺少实际执行或机制观测证据；不判定方向无效 |
| 机制未生效 | 有证据显示未走预期路径；检查接入和分发条件 |
| 机制生效、无性能收益 | 探索成本转移、负载适用性，或结束该条件下的方向 |
| 性能改善、质量失败 | 保留失败证据，定位语义或数值问题，不晋升 |
| 测量无效或证据不足 | 保持未知，按原有规则处理，不虚构收益 |
| 正式接受 | 保存适用条件和独立准入结果 |

状态更新必须有来源。任务类别、路径等 Agent 标签可以辅助检索，但不能仅凭自动标签屏蔽候选。完全相同候选的重复检查继续存在；同一方向的重试须说明前提或实现发生了何种实质变化。

验收：历史检索能区分“同文件、不同机制”；失败实现不会自动变成方向否定；质量或完整性失败不会被性能点估计覆盖。

### P0-C：复杂改动的独立只读复核

借鉴 VibeServe 和 EngineAgent 的独立上下文审查。实现完成、必要检查通过后，顺序调用同一本地稳定模型的新会话，只读任务卡、真实 diff、接口契约和检查结果。

复核重点：

- 改动是否接入真实请求路径、是否实现任务卡中的机制。
- 是否引入额外计算、权重副本、同步或跨请求状态污染。
- prefill、decode、并发及缓存条件是否处理完整。
- 是否改变固定约束、采样语义或绕过真实推理。

输出应包含问题、代码位置、依据、确认程度。复核者不修改候选、不宣告性能通过；反馈交由实现者处理，首期最多增加一次修复及一次复核，超出预算按普通失败处理。完整性异常立即沿用停止规则。

配置微调优先使用确定性检查；forward 替换、缓存、调度、自定义 kernel 等复杂改动才启用模型复核。触发范围做成显式可配置策略。

验收：新会话不继承实现者的完整对话；无写入工具；可追溯实际审查 diff；复核时稳定引擎仍承载本地 Agent；重启及宿主准入流程不变。

### P1-A：选择与实现分阶段

本地模型先完成选题，最多比较两个有证据的假设，输出任务卡；实现阶段仅接收任务卡、必要源码和相关历史。可先在同一会话中分阶段，验证后再启用新上下文，避免无依据增加开销。

实现阶段围绕一个假设，允许完成该假设所必需的跨文件修改。若改题，必须更新任务卡并说明新证据。允许探索，不设机械的“第 N 次工具调用必须改代码”门槛。

验收：阶段切换保留约束与必要事实；不会因为裁剪上下文丢失真实报错；分别记录选题和实现耗时。

### P1-B：快速探测反馈机制是否兑现

复用现有 `probe()`。将任务卡中的预期观测与宿主可可靠采集的字段对应，例如同步调用、kernel launch、实际 batch、队列时间和替换路径调用证据。

- 原始观测、派生量和 Agent 的因果解释分开保存。
- 对照稳定与候选时核对场景和测量方式；无法可靠测量时为未知。
- 路径被加载不等于被调用，调用发生不等于更快。
- GPU 结果在候选重启后采集，进入下一轮反馈；不增加候选与稳定之间的当轮来回切换。
- 探测不用于晋升，不替代正式功能、质量与配对性能准入。

验收：可以回答“机制未生效”与“机制生效但无收益”的区别；诊断开销可测；观测缺失不会伪装成机制失败。

### P1-C：决策预算与任务工作记忆

按选题、实现、CPU 修复和复核记录 token、工具、耗时与退出原因；设置有限预算，避免新增角色使一轮无限延长。

工作记忆优先保存：当前任务卡、已确认事实、已读符号、当前 diff 身份、未解决错误和下一个动作。长输出保存完整日志，仅回读必要范围。连续工具调用没有产生新事实时，要求说明缺失证据和有针对性的下一步，而非机械重复搜索。

验收：摘要后可定位原始证据；截断和工具失败不被视为完成；预算耗尽保留现场，稳定版本与完整性规则不变。

## 4. 实施顺序

1. 补充最小观测：每轮各阶段耗时、输入输出 tokens、候选提交及失败类型；确认已有字段可复用的部分。
2. 实施 P0-A 与 P0-B：证据包、任务卡及假设状态，在现有上下文和经验模块中增量接入。
3. 实施 P0-C：仅为复杂源码改动启用同一本地模型的独立只读复核，明确预算。
4. 根据观测决定是否将选题与实现拆成新会话；再增加探测字段对照和工作记忆裁剪。
5. 在新的实验请求下进行控制实验，逐项启用，记录真实收益与额外成本。

每项用开关或兼容路径逐步引入；未启用时保持既有行为。不引入新的稳定晋升渠道，不为中间机制通过放宽最终门槛。

## 5. 检查与实验设计

实现时运行对应回归检查及 CPU 流程验证；覆盖缺失观测、无历史、失败实现、未激活路径、相同源码不同条件、上下文裁剪与复核预算耗尽。不得将 CPU 检查通过解释为 GPU 加速。

正式对照保持目标模型、Agent 本地模型、硬件、精度、负载、准入和总墙钟预算一致；每次使用新输出目录，不跨运行导入历史。Agent 推理具有随机性时需重复对照，而非只比较一次最好结果。

主要指标：

- 相对同一初始引擎的最终累计正式收益。
- 达到指定收益所需时间；未达到时明确记录。
- 每小时具备评测条件的候选数、正式接受数。
- 构建、功能、质量和性能各阶段通过率及失败分布。
- 重复失败比例，方向重试是否有新证据。
- 勘测、模型启停、选题、实现、修复、复核、质量与性能评测的耗时分布。

不预设收益百分比。若复核降低错误候选但耗时更大，需用固定预算下的总收益判断是否保留。各轮收益不可直接相加，测量无效与完整性异常单独报告。
