# 功能、质量与性能准入

候选依次经过功能检查、独立质量、正式配对性能及激活检查，全部合格才更新稳定版本。模型、硬件、精度、负载、上下文和输出契约在运行开始时固定。

## 功能检查

Qwen/A800 配置默认 `evaluation.correctness_mode=quality`：输入 tokenization、输出类型与范围、固定工作量、数值有限性、请求隔离和运行异常是硬检查；相对初始引擎的 token/logits 分布差异作为保真度诊断。功能通过仍须执行质量准入。

隔离检查覆盖交错 A→B→A 和不同长度并发请求。非合批并发结果须与独立请求一致；合批结果分叉时，在同一单请求前缀查询 logits，按 `batch_divergence_max_logit_gap`（默认 0.5）识别近似平局，记录通过的分叉并继续质量检查。超过阈值拒绝。这不等于已覆盖所有 KV-cache 错误或完成全面数值容差校准。

`strict` 保留逐 token 与抽样 logits 硬门槛；`approximate` 保留 token 一致率策略。不同模式的通过含义不同，不能混用结论。

## 独立质量

默认使用 `benchmarks/task-quality-50.json`，基线与候选各执行一遍：core 10、算术 12、字符串/阅读/逻辑各 6、代码 6、工具 4 题。输入、断言和答案在运行前冻结并哈希。代码题在受限临时子进程执行断言，工具题由可信评测逻辑执行。

`paired.decision_mode=observed_loss`、`min_cases=50`：统计同题基线通过而候选失败的比例，最多 5%；新增答对不抵消新增失败。core 正确率至少 0.8，且必须满足配置中的总体及类别退化保护。类别允许下降的粒度为 `max(max_regressions[类别], category_item_tolerance / 题数)`；默认至少允许一题的离散步长，并不取消总体门槛。

相同任务跨遍按 AND 聚合，重复不增加独立题数。50 题即使零损失，单侧 95% 损失率上界仍约为 5.82%，因此这是固定题集经验筛查，不是满足 5% 置信上界的质量保持证明。`confidence_bound` 模式仍保留，用于需要置信上界硬门槛的配置。

`python scripts/build_quality_suite.py` 可重建固定 50 题；`--size 150` 重建扩充集。模板题相关、长上下文和复杂多工具覆盖有限，不能视为生产任务或公开榜单保证。

## 正式性能

性能目标以冻结的 `evaluation.objective` 为准。`request_output_tokens_per_second_mean` 是逐请求计算实际输出 token 数 / 客户端端到端耗时（含预填充、排队和生成）后取均值，多场景按固定权重取几何平均。

默认 5 组 AB/BA 配对，置信下界超过 2% 最小收益、各场景退化不超过 3%，并满足设备独占、连续遥测及污染检查；部分配置另有延迟保护。并发总 tokens/s、decode tokens/s 只作辅助。快速探测及质量失败后的探索测速不能用于晋升。

详细 token 计时通过 `evaluation.collect_token_timing` 开启，比较双方使用相同计时方式。并发或合批路径无法可靠采集的 TTFT/TPOT 保持 null；内部 token 就绪时间不等于客户端流式首字节时间。小样本 p95/p99 只作描述。

收益只适用于本次固定负载，各轮收益不可直接相加。只有真实加载状态与实际请求路径能确认配置生效；配置变更本身不证明性能改善。

## 失败处理

普通构建、功能、质量或性能失败：拒绝候选，保留稳定版本，继续下一轮。共享依赖、宿主、稳定源码或冻结材料完整性无法验证：停止整次运行并诊断，禁止绕过失败标记自动恢复。恢复规则见 [运维说明](operations.md)。
